## 1. 现状诊断（实测，非推测）

### 1.1 四个田园音源：全程无静音段

| 音源 | 现役时长 | RMS 范围 | >0.4s 静音段（-45dB 阈值） |
|---|---|---|---|
| `dog-bark` 狗叫 | 16.8s | -26.3 ~ -14.1 dB | **0** |
| `chicken` 鸡叫 | 10.3s | -28.1 ~ -14.8 dB | **0** |
| `goose` 鹅叫 | 60.0s | -40.9 ~ -12.9 dB | **0** |
| `pond` 池塘 | 28.9s | -19.2 ~ -11.9 dB | **0** |

即四个文件在任意 0.4s 以上都没有安静窗口，能量包络全程饱满。狗叫 / 鸡叫 / 鹅叫又都是**短素材整段循环**（16.8s / 10.3s），重复感更强——这就是「一直不停叫」的直接来源。
`pond` 属于环境底噪型（水声+鸭群），本就不该有间歇，**保持不动**。

### 1.2 雨声：循环点存在 4.6 dB 电平凹陷

两个雨声同为 59.02s，均由 `app/tools/fetch_audio_assets.py` 的 `make_loop()` 生成：

```
裁切 → loudnorm(I=-18) → 取开头 1s 与主体做 acrossfade(d=1s, c1=tri, c2=tri) → AAC 128k
```

50ms 分辨率能量包络实测：

| 音源 | 中段均值 | 开头 1s | 结尾 1s | 首尾落差 |
|---|---|---|---|---|
| `rain-light` 小雨 | -18.0 dB | -18.9 dB | **-23.5 dB** | **-4.6 dB** |
| `rain-heavy` 大雨 | -23.5 dB | -23.9 dB | -25.4 dB | -1.5 dB |

三个叠加原因：

1. **线性 `tri` 淡化对不相关噪声会掉能量**：两段独立噪声线性相加，交叉区中点天然约 -3dB 凹陷；等功率（`qsin`）才能保持能量恒定；
2. **1s 淡化太长**：整整 1 秒都在渐变，雨声的颗粒被抹平，听感上像「抽空一下」；
3. **头段取的是源录音开头 1s**：往往与主体音色 / 电平不一致，环绕后尾部音色跳变；且 59s 循环太短，重复感每周一次很扎耳。

> 说明：早前用 `ffmpeg -ss 59` 测出的 -44.9dB 是越界 seek 只读到 24ms 尾帧的假象，以上 50ms 包络为准。

`app/tools/fetch_rural_assets.py` 用的是同一套 `tri` 环绕链，所以**风、田园四声也有同类隐患**，需一并回归。

## 2. 改进方案

### A. 动物叫声间歇化 —— 文件级「事件编排」

**关键决策：把节奏烤进音频文件，而不是加运行时调度。** 这样 App 端零代码改动，试听页能直接复现真实循环效果，确认后只需替换文件。

处理链：
```
源素材 → 按能量切出单个叫声事件 → 建事件库（去噪/去爆音/统一响度）
       → 按节奏表把事件摆进 90~120s 时间轴
       → 边界前后各留 ≥3s 静场（保证循环点不会切断事件）
       → 整体 loudnorm + 峰值限制 → AAC 128k → .m4a
```

节奏表（默认「中」档，另出一档「疏」供 A/B）：

| 音源 | 事件形态 | 组间隔 | 事件占比 | 循环长度 |
|---|---|---|---|---|
| 狗叫 | 2~3 声连叫为一组（0.8~2.0s），偶尔远处单声 | 8~18s | ≤15% | 100s |
| 鹅叫 | 1~3 声一组，可点缀扑翅/落水 | 12~28s | ≤12% | 110s |
| 公鸡打鸣 `rooster-crow` | 单声 1.2~2.5s，清晨感，不宜密 | 25~55s | ≤8% | 120s |
| 母鸡咯咯哒 `hen-cackle` | 一串 2~4s（产蛋后典型咯咯哒） | 20~45s | ≤10% | 110s |

反重复措施：间隔用固定种子的伪随机序列、同一事件不连续复用、每次 ±5% 增益 / ±3% 变速微调、循环长度互不相等（避免多轨叠加时节奏同步）。

另出一组对照变体：**纯事件**（间隙为静音）vs **事件 + 低电平田园底噪**（-30dB 左右微风/远处环境），供试听时二选一。

### B. 雨声无缝循环 —— 重做处理链

| 步骤 | 做法 |
|---|---|
| 1 取长素材 | 从原始录音取 ≥90s（不再裁到 60s） |
| 2 找循环点 | 在 60~90s 区间按短时频谱 + RMS 相似度搜索与开头最匹配的点（自动化，不靠听感猜） |
| 3 短淡化 | 等功率 `acrossfade(c1=qsin:c2=qsin)`，**100~200ms**（噪声只需短淡化，避免长渐变抹平颗粒） |
| 4 统一响度 | `loudnorm I=-18 TP=-2 LRA=11`，与其余音源一致 |
| 5 验收 | 边界前后各 0.25s RMS 差 **< 1.5dB**；连续循环 5 次盲听找不出循环点 |

同时新增 `tools/check_loop_seam.py`，对全部 23 个现役音源跑一遍首尾落差检测，把有同类问题的音源列出来（预计风、雷、田园类需一并修）。

**体积权衡**：循环从 59s 拉到 75~90s，单个音源约 +20~50KB×秒数；全部雨声+田园重制后，APK 预计增加 3~6MB（当前 release 35.6MB，可接受）。

### C. 鸡叫拆分

- 新增两个独立音源：`rooster-crow`（公鸡打鸣）、`hen-cackle`（母鸡产蛋后咯咯哒），各自按 A 的节奏表做间歇；
- 旧 `chicken`（Chickens demanding food，Public domain）语义是「讨食的鸡群」，与两者都不同；
- **建议**：试听确认后，用两个新音源**替换** `chicken`，避免声音库里出现三个鸡类条目；
- `sound_glyph.dart` 现有 `_henBody` 可复用，需补一个公鸡线性图标（鸡冠 + 长尾羽）和咯咯哒（声波线）区分；
- 素材候选：`File:Rooster crowing small.ogv`（视频，需抽音轨并核验授权）、母鸡咯咯类 Commons 录音；**授权元数据在阶段 1 逐条核验**，不合规的候选直接弃用。

## 3. 试听交付方式（阶段 1~2）

```
preview/
├── audio/           候选 m4a，命名 cand-<id>-<variant>.m4a
│                   （含现役对照副本 ref-*.m4a）
├── audio/授权候选.csv
└── index.html       试听页（纯静态，本地打开即用）
```

试听页功能：

1. **A/B 对照**：每个音源「现役」与「候选」并排，一键切换；
2. **单轨循环**：可开「连续循环 5 次」，专门听循环点是否可辨；
3. **多轨叠加**：最多 3 轨同时播放（模拟混音台），验证间歇节奏在叠加时是否显得吵或过于稀疏；
4. **变体切换**：疏 / 中密度、纯事件 / 带底噪；
5. 每个条目标注时长、事件数、首尾落差实测值。

建议试听维度：① 间隔是否自然、有没有「等太久」；② 循环点还听不听得出来；③ 与其他轨叠加是否打架；④ 夜间低音量下会不会突然被某一声吓到。

## 7. v1.2 试听反馈修订（2026-11-15）

> 本节是对第 1~3 节的**实测更正**：v1.1 的雨声处理链（原始 Commons 素材 + `loudnorm` + 首尾 RMS 差选点）经试听验证不成立，已废弃。前文章节保留作为决策记录。

### 7.1 三条反馈与处置

| # | 反馈 | 处置 | 实测 |
|---|---|---|---|
| 1 | 间隔太疏、太规律 | 簇数固定保证密度可控（狗 11/17 簇、鹅 10/16、公鸡 7/11、母鸡 8/13），间隔改指数分布 + 活跃度调制 + 长尾截断 | 中档每分钟 6.0~13.8 声（上一版约 2.5~9），CV 0.56~0.67（等间隔约 0.2），最长间隔 ≤ 均值 2.4 倍 |
| 2 | 能否有远近控制 | 预渲染近/中/远三档：音量 0/−5/−10dB、低通 全频/4.2k/2k、声像收窄、早期反射 | 4 音源 × 3 档 = 12 个样本；正式引入建议改为 App 端每轨连续参数 |
| 3 | 雨声不像雨、循环割裂 | 见 7.2 | seam 0.73 / 0.17dB，首尾音色差 2.24 / 0.78dB |

### 7.2 雨声：真正的原因与修正

| 项 | 实测 | 结论 |
|---|---|---|
| 4kHz 以上能量占比 | 现役 8.3% / 9.5%，v1.1 候选 1.3% / 0.2%，原始 Commons 源 1.0% / 0.3% | 候选沿用了原始素材的低频轰鸣，没复现现役的雨滴高频沙沙声 |
| 短时电平起伏 σ | 现役 0.43~1.35dB，候选 2.70~2.83dB | `loudnorm` 动态增益引入抽吸，并破坏首尾一致性 |
| 循环点指标 | 旧版只优化首尾 0.25s RMS 差 | 能量相近不代表音色相同，「接缝处换了个声音」测不出来 |

**修正**：以 `app/assets/audio/rain-*.m4a`（现役、已获认可）为唯一源，**完全不做 EQ / 响度归一**；在 PCM 层做 wrap-around 等功率交叉淡化（`out[0]=S[L]`、`out[L-1]=S[L-1]`，循环点是源里天然相邻的两个样本），按首尾 0.25s 的 RMS + 零交叉率搜索最佳起点与长度；输出无压缩 WAV（试听默认，排除 AAC 编码边界）与 192k M4A（落地对照）。

**验收**：小雨 seam 5.23→0.73dB、首尾音色差 7.65→2.24dB、边界跳变比 0.61→0.15；大雨 0.79→0.17dB、2.53→0.78dB、边界比 0.96→0.42。

### 7.3 循环指标口径修正

- 循环落差改为按**解码后的真实样本数**取首尾窗口，不再用 `ffprobe` 时长——AAC 尾部 padding 曾误测出 8dB 假落差；
- 选点评分必须与验收**同为双声道功率平均**。只算左声道时风声右声道可差 3.59dB，选出的点成品仍有 3dB 落差；统一口径后 16 个事件候选全部回落到 0.00~0.14dB。

### 7.4 待确认

1. 「间隔过于规律」按「想要更自然、不要机械」处理；若本意是想要更规整，`preview/tools/build_candidates.py` 的 `RHYTHM_MODE` 改为 `even` 即可一键切回等间隔；
2. 若只有 M4A 听得出接缝而 WAV 听不出，说明是 AAC 解码器在 loop 时重置造成的，正式引入需 App 端用 gapless 播放（或改用无压缩格式）；
3. 远近目前是 3 个离散档，方向认可后再决定是否做成连续参数。

### 8.8 起始留白修复（r2，2026-11-15）

用户装机反馈：狗 / 鹅 / 公鸡 / 母鸡「起始的位置不要空着」。

根因：`make_timeline` 从 `head = rng.uniform(2.0, 3.5)` 起排、末尾
`tail = 3.0` 收尾，而第一个事件还要再等一个随机间隔；实测 r1 文件开头
5.00~13.31s 才出第一声，循环时首尾静音又叠加成 8.10~21.37s 停顿（见 8.6）。

修复：`rotate_to_start()` 环形相位旋转。把时间轴视为环，切点选在一对相邻
事件之间的静音里（要求旋转后首尾各留 ≥0.35s 静音、不截断任何事件，并优先
挑间隔接近平均值的那段），再按切点展开成线性时间轴。事件相对间隔、密度、
CV 全部不变，只改变循环起点：

- 文件 0.35~0.55s 出第一声；
- 循环点间隔 = 环上那对事件原本的间隔（与节奏同量级），不再首尾叠加。

落地实测（中-silent，`silencedetect -50dB`）：

| 音源 | r1 起始 | r2 起始 | r1 循环点 | r2 循环点 | r2 seam |
|---|---|---|---|---|---|
| 狗叫 | 13.31s | 0.37s | 16.61s | 4.36s | 0.00dB |
| 鹅叫 | 5.00s | 0.47s | 8.10s | 4.21s | 0.00dB |
| 公鸡 | 10.31s | 0.54s | 21.37s | 8.18s | 0.00dB |
| 母鸡 | 5.89s | 0.50s | 13.31s | 4.54s | 0.00dB |

16 个事件候选 seam 0.00~0.14dB 全部达标；实测首段静音与 manifest 计算值
一致（误差 ≤0.04s，来自事件素材自带的 40ms 前导静音）。距离三档、
`manifest.json` / `.js`、试听页 meta 已同步；**雨声两个文件未改动**，
SHA1 保持 `672810DC…` / `D03F38E2…`。

回滚：`backup/audio-v1.1-r1/` 保存 r1 的 4 个文件（含 `说明.txt`），
v1.0.0 原件仍在 `backup/audio-v1.0.0/`，两层备份不要混用。

v1.0.0 备份读取，避免 app 现役被替换后全量重建取错源、或因 `chicken.m4a`

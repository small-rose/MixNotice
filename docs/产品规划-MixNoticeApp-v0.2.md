# MixNotice App 产品规划（v0.2）

> 一句话定位：一款桌面端 + 移动端双端的自然声音混音应用——聆听自然、自由组合多轨声音、伴着声音入睡或休息。
> 参考对象：Noisli（多音轨混音 + 计时器）、Tide 潮汐（专注/睡眠/放松场景化）、TaoMix（自然声景自由混音）——仅借鉴通用产品模式与交互范式，不复刻其文案、视觉与专有音频素材。

## 一、背景与目标

### 1.1 背景
- 用户对「氛围声音」的需求集中在三类高频场景：**入睡助眠**、**专注工作/学习**、**工作间隙休息放松**。
- 现有产品验证了「多音轨自由混音 + 倒计时」是核心心智，但各有短板：桌面端体验弱、中文场景化不足、自定义混音分享不便。
- 本项目机会：**双端一致的声音混音体验**（移动端睡前用、桌面端工作时用），以「混音方案跨端同步」为差异化切入点，并以订阅制完成商业化闭环。

### 1.2 成功指标（口径：上线后 30 天自然周期）
| 指标 | 目标值（估算） | 口径 |
|------|----------------|------|
| 次日留存 | ≥ 35% | 新增用户次日回访率 |
| 人均单日使用时长 | ≥ 25 分钟 | 前台播放累计时长 |
| 混音方案保存率 | ≥ 40% | 使用 ≥3 次的用户中保存过自定义方案占比 |
| 睡眠倒计时使用占比 | ≥ 50% | 含倒计时启动的会话 / 总会话数 |
| 免费转订阅率 | ≥ 3% | 月活跃用户中开通付费订阅占比（行业基准估算，上线后校准） |
| 体验次数转化贡献 | ≥ 25% | 首次付费用户中经由「免费体验次数」路径转化的占比 |

## 二、目标用户与场景

### 2.1 用户画像（待确认假设）
| 画像 | 身份 | 核心场景 | 痛点 |
|------|------|----------|------|
| 助眠族 | 22-35 岁都市白领 | 睡前戴耳机听雨声/海浪入睡 | 手机息屏后播放中断、声音单一易腻 |
| 专注族 | 程序员/写作者/学生 | 桌面端工作时开白噪音/咖啡厅声屏蔽干扰 | 想要「不切窗口就能调音量/换方案」 |
| 休息族 | 办公室人群 | 工作间隙 5-15 分钟闭目放松 | 缺少「到点轻声提醒回来」的休息计时 |

### 2.2 核心用户故事
1. 作为**助眠用户**，我想要「雨声 + 远雷 + 篝火」三轨混音并设定 30 分钟睡眠倒计时（音量渐弱至静音），以便自然入睡而不被关掉声音吵醒。
2. 作为**专注用户**，我想要桌面端托盘一键切换「森林晨鸟」方案、暂停/恢复播放，以便不打断工作流。
3. 作为**休息用户**，我想要 10 分钟休息倒计时并配舒缓音景、结束时轻柔提示，以便定时回归工作。
4. 作为**免费用户**，我想要每月若干次解锁全部音源的完整体验，以便充分感受价值后再决定是否订阅。

### 3.2 V1.1（账号 + 商业化启动）
- 账号体系（手机号/第三方登录）+ 混音方案**跨端同步**（差异化核心，订阅权益之一）。
- **订阅制上线**：月度/年度自动续费订阅（方案见 6.1），免费体验次数机制切换为服务端计数。
- 防破解体系上线（见第七章）；桌面端**快捷键**与全局悬浮球。
- 每轨**空间方位/左右声道偏移**；音量自动化（某轨随时间起伏，模拟真实声景）。

### 3.3 V2.0（增长与生态）
- 本地导入自定义音频（用户自备素材，规避版权风险）；录制并分享「声景卡片」（方案参数可视化分享，他人一键试听）。
- 场景化内容包（专注/冥想引导/雨夜故事等）纳入订阅权益池或单独售卖（待 V1.1 数据验证后决策）。

## 四、信息架构与页面清单

**导航策略**：移动端底部 Tab（3 个）+ 桌面端左侧边栏（同构），保证双端心智一致。

| 页面 | 核心内容 | 主要操作 | 端差异 |
|------|----------|----------|--------|
| 声音库（首页） | 按自然/噪音/生活分组的音源网格 | 点按试听、加入当前混音 | 桌面端支持拖拽入混音台 |
| 混音台 | 音轨卡片（名称+波形+音量滑杆+单独静音） | 调音量、移除音轨、保存方案 | 桌面端常驻主窗口 |
| 方案库 | 预设 + 我的方案列表 | 一键播放、编辑、删除 | — |
| 计时器 | 睡眠/休息两个页签，大字倒计时环 | 选时长、启动、取消、联动方案 | 桌面端可缩为托盘小窗 |
| 会员页（V1.1） | 订阅方案、免费体验次数余量与刷新日、权益对比表 | 开通/管理订阅、恢复购买 | 桌面端走扫码/网页支付 |
| 设置 | 音质、默认方案、开机自启（桌面）、通知偏好、关于与授权清单 | 开关与选择 | 分端配置 |

**任务流**：选声音 → 调混音 → （可选）保存方案 → 设倒计时 → 播放/离开。核心路径 ≤ 3 步关键操作。

## 五、技术选型

### 5.1 跨端方案（已确认双端并行）
| 方案 | 跨端覆盖 | 双端并行适配性 | 成本 | 综合评价 |
|------|----------|----------------|------|----------|
| A. Flutter 单代码库 | iOS/Android/Win/macOS | 高：UI 同构、业务逻辑 100% 共享，双端仅平台适配层（托盘/通知/后台播放/内购桥接）各自实现 | 中 | **推荐**：并行开发的最优解 |
| B. React Native + Electron | 全覆盖 | 中：两套 UI 需两个小组，逻辑易漂移 | 高 | 备选 |
| C. 各端原生 | 全覆盖 | 低：三套代码 | 最高 | 不推荐 |

### 5.2 音频引擎（MVP 方案）
- 本地解码 + 多实例叠加播放（`just_audio` 类方案），音轨预处理为无缝循环的 AAC/OGG（循环对齐 + 交叉淡化）。
- 睡眠倒计时渐弱在**应用层**按帧调音量实现，保证双端行为一致。

### 5.3 客户端/服务端分工（V1.1 商业化后）
- **客户端**：播放、混音、计时器全部本地完成（弱网/离线可用）；本地票据缓存（加密）。
- **服务端**：账号、订阅状态、体验次数计数（服务端为准）、收据校验、防破解校验接口。
- **原则**：权益判定以服务端为准，客户端缓存仅用于离线宽限（见 7.2）。

## 六、商业化设计（订阅制）

### 6.1 订阅方案（定价为估算，上线前需专项定价调研）
| 档位 | 价格（估算） | 权益 |
|------|--------------|------|
| 免费版 | ¥0 | 基础 8 个音源、最多 3 轨混音、3 个自定义方案、完整倒计时功能 |
| 月度订阅 | ¥8/月 | 全部 16+ 音源、6 轨混音、无限方案、跨端同步、后续新音源/内容包 |
| 年度订阅 | ¥48/年（折合 ¥4/月） | 同月度权益，突出性价比锚点 |
| 买断制 | 不提供 | 明确不做，保持订阅心智（后续可依数据复议） |

### 6.2 免费体验次数机制
| 规则项 | 设计 |
|--------|------|
| 体验内容 | 每次体验 = 一个自然月内 N 次（建议 N=10，估算值）「完整体验会话」：单次会话内解锁全部音源 + 6 轨混音，会话随停止播放结束 |
| 计数与刷新 | 每自然月 1 日刷新（服务端按账号计算，客户端展示余量）；V1.0 免登录阶段为本地计数（仅预热展示，不上锁） |
| 次数用尽后 | 降级为免费版权益，不中断当次正在播放的会话（体验中不打断）；弹窗提示余量与订阅入口，每月最多提醒 2 次防骚扰 |
| 提示时机 | 余量 ≤3 次时在计时器/混音台轻提示；用尽后进入会员页一次引导 |
| 防刷 | V1.1 服务端计数后，同一账号为唯一计量单位；异常高频新建账号行为接入风控限制（同设备指纹注册限频） |

### 6.3 支付与自动续费
- 移动端：iOS 走 App Store 内购、Android 走 Google Play / 国内应用商店内购（数字内容必须走平台内购，抽成 15-30% 已计入定价模型）。
- 桌面端：自有支付（微信/支付宝扫码 + 网页收银台），无平台抽成，是利润最优入口。
- 自动续费合规（国内监管要求，必做）：开通前明示价格/周期/扣费规则；续费扣款前（≥24h）推送提醒；随时可取消，取消路径 ≤3 步且不设障碍；扣款失败有宽限期与补扣提醒。

### 6.4 订阅资金安全三件套（底线，任何排期压缩不得砍除）
| 项 | 要求 |
|----|------|
| 幂等 | 订阅开通/续费/退款以「订单号 + 渠道流水号」为幂等键，重复回调不重复入账、不重复发放权益 |
| 对账 | 与 App Store / Play / 支付渠道的日对账任务 + 差异留痕与人工处理流程；订阅状态以对账结果可追溯为准 |
| 资损监控 | 告警四类：同一订单重复支付回调、负金额/异常金额、订阅状态回跳（已退款仍为会员）、对账差异超阈值 |
| 退款口径 | 支持按渠道规则退款（iOS 由苹果受理），退款即时/次日收回订阅权益；部分退款不适用（订阅为整期） |
| 金额精度 | 金额以分（整数）存储与计算，禁止浮点；价格展示与扣费金额一致 |

## 七、防破解专项

### 7.1 总体边界（先说清楚）
客户端防破解只能**提高破解门槛与成本**，无法做到绝对防破解；设计目标是：让破解成本 > 订阅价格 × 合理倍数，并使核心权益依赖服务端，即使客户端被篡改也拿不到权益。

### 7.2 分层防护设计
| 层 | 措施 | 说明 |
|----|------|------|
| 权益层（核心） | 订阅状态、体验次数计数、付费音源包下载链接全部由服务端下发与校验 | 音频文件 URL 带短时效签名（防盗链），即使账号被盗用也无法批量扒取素材 |
| 传输层 | 全链路 HTTPS + 接口签名（防篡改、防重放：时间戳 + nonce） | 关键接口响应附带服务端签名，客户端校验 |
| 票据层 | 订阅凭证服务端签发（含过期时间、设备数上限），本地加密存储（平台安全存储：Keychain/Keystore/DPAPI） | 离线宽限期 ≤7 天（票据有效期内可用），过期必须联网刷新——防止拔网线永久白嫖 |
| 收据层 | App Store / Play 收据一律服务端验证（server-side receipt validation），禁止客户端自行判真伪 | 防伪造收据解锁 |
| 设备层 | 账号同一线程内设备数上限（建议 5 台，同时在线 2 台），超限强制下线最早设备 | 防一号多卖共用 |
| 客户端加固 | 代码混淆、资源加密（音频包分片 + 自定义容器格式）、防调试/防 Hook 基础检测、完整性自检（签名校验） | 抬高逆向成本；桌面端重点防本地破解补丁 |
| 灰产对抗 | 服务端风控：异常下载频次、异地多设备同时播放、批量注册识别，命中后限速/冻结 + 申诉通道 | 防工作室批量薅羊毛（免费体验次数是主要被刷点） |

### 7.3 应急与体验平衡
- 校验服务异常时的策略：**宁可短暂全量放行也不误伤付费用户**（降级为最近一次服务端确认的权益快照），服务恢复后重新校验。
- 所有防破解误判场景提供人工申诉入口，48h 内响应。

## 八、非功能需求（关键项）
- **性能**：6 轨同时播放，移动端 CPU ≤ 15%（中端机），桌面端内存 ≤ 250MB；启动到可播放 ≤ 2s。
- **续航**：移动端息屏播放 1 小时耗电 ≤ 5%（估算，需实测校准）。
- **兼容**：iOS 14+ / Android 8+ / Windows 10+ / macOS 12+。
- **合规**：音频素材全部 CC0 或书面商用授权并存档；隐私政策（匿名使用数据；V1.1 起按账号收集最小必要数据）；订阅页明示自动续费规则；不做诱导付费。

## 十、里程碑（双端并行，估算待资源确认）

双端并行可行性结论：**可以**。Flutter 单代码库下 UI 与业务逻辑完全共享，双端差异集中在平台适配层（托盘/通知/后台播放/内购），可由同一团队按「平台适配」分工并行推进；代价是总工期比单端先行约多 2 周，或需增配 1 名端侧开发保持 8 周。

| 阶段 | 内容 | 周期（估算） |
|------|------|--------------|
| W1-W2 | 技术预研（Flutter 音频 PoC + 安卓息屏 + 桌面托盘 + 内购沙箱）+ PRD 评审定稿 | 2 周 |
| W3-W7 | MVP 双端并行开发（音库/混音台/双计时器/后台播放；移动线与桌面适配线并行） | 5 周 |
| W8 | 双端联调 + 真机测试矩阵 + 听感验收 | 1 周 |
| W9 | V1.0 双端同步灰度发布 → 收集反馈 | 1 周 |
| W10-W13 | V1.1：账号 + 订阅 + 防破解体系开发与资金专项评审 | 4 周 |
